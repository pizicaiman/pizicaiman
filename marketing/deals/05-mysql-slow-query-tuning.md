# MySQL 慢查询优化专项 · 小合作单品

## 一句话价值
把"卡"在数据库的体验，从根上治掉。

## 适用场景
- 业务接口偶发慢、高峰卡顿，定位到数据库。
- 慢查询日志堆积，无人系统分析。
- 准备大促或业务上量，需提前治慢。

## 交付内容
- 慢查询日志采集与 TOP 慢 SQL 分析。
- 执行计划解读与索引优化建议。
- 表结构与查询写法评审。
- 优化前后对比验证。
- 《慢查询优化报告》+ 可执行改进清单。

## 交付方式
- 远程协同，基于客户提供的环境与数据。
- 输出优化报告 + 关键 SQL 改写建议。

## 交付边界（不包含）
- 不含应用层 ORM/代码改造实施。
- 不含数据库架构级改造（主从/分库分表，见方案 E）。
- 不含数据迁移。

## 配套能力
数据库与数据存储。

## 适配
- 口号：05-db-middleware（数据不丢、不慢、不断）
- 方案 E：数据库与中间件治理方案

## 客户常问 3 问（FAQ）

**Q1：这个包含应用层 ORM 代码改造吗？**
不包含。本单品聚焦 SQL 与索引层面分析与建议，不含 ORM/代码改造实施。架构级改造见方案 E。

**Q2：需要我们配合什么？多久能完成？**
需提供慢查询日志、表结构与生产可访问环境用于执行计划分析。通常 1-2 周完成，按项目计费。

**Q3：做完之后效果能维持多久？**
优化后可立即缓解当前慢查询瓶颈，但随数据量与业务变化仍需定期复查。建议结合容量规划定期跟进。
